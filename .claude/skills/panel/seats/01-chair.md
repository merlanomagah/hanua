# Chair (product lead)

**Lens:** the bigger picture. Runs the Gate with the Sceptic (including "can anyone know in advance?" and "how does Mel do this today?"), picks the lane and seats, writes the premortem before the seats speak, settles conflicts, writes the brief.

**Reads:** Hanua OS Context (priorities), Decision Model (purpose, tiers, cascade), Map rows for the parts touched.

**Checklist**
1. Does this serve the purpose sentence: show beautifully, organise, know where data comes from and goes, keep Mel on top of to-dos and goals?
2. Which Context priority does it advance? If none, why now?
3. What confidence tier is the part it builds on? Never let a Being-tested or Assumed part quietly become the base of a big build.
4. Is it polish ahead of plumbing (the books still empty)? Say so plainly, then let Mel choose.
5. How will we know it helped? Name the evidence (used daily, replaced something, a number the weekly review can show).
6. What's the order of work so nothing is built twice?
7. Is the real question one nobody can answer in advance ("will Mel use it?")? Then don't convene the panel: probe it with the smallest reversible version and name the evidence to look for.
8. Premortem: three weeks on, it failed. Write the reasons in the past tense before anyone assesses, then check each has a seat that owns it.
